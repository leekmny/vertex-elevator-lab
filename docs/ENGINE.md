# 결정적 이산 사건 엔진

`src/sim`은 React, DOM, Canvas, Worker와 독립적입니다. 모든 시각의 단위는 초, 이동 거리는 m, 속도는 m/s, 가속도는 m/s²입니다. 지하층은 내부 좌표 `1-basements .. 0`이며 0을 B1으로 표시합니다. 1층과 B1 사이도 한 층 높이입니다.

## 재현과 사건 순서

수요는 Mulberry32 기반 Seed 난수로 먼저 생성합니다. 기본 100%는 **건물 전체 분당 24명**입니다. 포아송 지수 간격을 사용하고 시간변화 시나리오는 60초 구간별 도착률을 사용합니다. 생성기 난수와 배차 탐색 난수는 분리됩니다. 동일 입력·Seed·버전에서 수요 해시, 사건, 통계가 동일합니다. 재생 속도와 snapshot 호출 빈도는 사건 순서를 변경하지 않습니다.

최소 힙 키는 `(발생 시각, 우선순위, 삽입 순번)`입니다. 같은 시각은 고장(5), 도착·문열림·하차·개별승차(10), 승차 계획(15), 문닫기 시작(16), 승객 등장·닫힘 완료(20), 구역 갱신(30), 배차(40), 표본 기록(90) 순서입니다. 동일 우선순위는 생성 순번으로 안정 정렬합니다. 동시에 등장한 호출은 배차 전에 모입니다. 개별 승차는 정원 확인과 상태 전이를 원자적으로 수행합니다.

종료 시각과 정확히 같은 시각의 사건도 모든 우선순위가 처리된 후 종료합니다. 한 사건씩 진행해 끝낸 결과와 일괄 실행 결과가 동일합니다. 수요 종료 시각이10초 표본 주기와 맞지 않아도 종료 경계를 별도 사건으로 기록하므로 빈 Drain 실험이 다음 표본까지 불필요하게 연장되지 않습니다.

## 물리 모델과 서비스

정지 상태에서 가속하고 다시 정지하는 대칭 삼각형/사다리꼴 속도 프로파일입니다. 거리 `d`, 최고속도 `v`, 가속도 `a`에 대해 `d <= v²/a`이면 `2√(d/a)`, 아니면 `d/v + v/a`입니다. 렌더러 좌표는 동일 프로파일을 보간합니다. Jerk, 진동, 로프 탄성, 층별 미세 조정은 포함하지 않습니다.

도착 → 문열림 → 하차(1명씩) → 승차(1명씩) → 문닫기 → 출발을 계산합니다. 탑승 대기는 승차 처리 완료 시각까지입니다. 탑승 후 이동시간에는 문닫힘, 중간 정차, 목적지 하차가 포함됩니다. 만원 차량은 추가 pickup을 건너뛰고 이미 탑승한 승객의 목적지를 서비스합니다. 출발한 차량의 경로는 다음 정차까지 고정되며 이동 중 새 호출로 즉각 감속·중간 삽입하지 않습니다. 이 제약은 모든 알고리즘에 동일합니다.

## 운영 정책과 환승

공용, 홀짝, 고정 구역, 동적 구역은 배차 선택과 분리됩니다. `static`, `dynamic` 알고리즘은 해당 구역 정책을 명시적으로 적용합니다. 1대에서는 모든 층을 담당합니다. 그룹은 자동 균등 또는 `groupCars`의 비대칭 개수입니다. 고정 경계는 변경할 수 있으며 세 구역 이상도 지원합니다. 각 구역은 로비와 설정된 환승층을 공용으로 서비스합니다.

서비스 가능 층 집합으로 무방향 그래프를 만들고 설정 시작 시 모든 층의 연결성을 검증합니다. 승객은 최소 승차 횟수 BFS 경로를 이용합니다. 환승 시 새로운 대기 사건을 만들고 누적 대기·승차 시간과 환승 횟수를 보존합니다. 별도 보행시간은 0초 가정입니다. 동적 구역은 30초마다 실제 대기 부하를 이용해 경계를 바꾸며 현재 예약·탑승 다리의 양끝 층을 보존합니다. 미예약 대기 승객과 환승 승객은 새 그래프에서 경로를 갱신합니다. 차량별 수동 서비스 제한과 조합해 연결성이 없어지면 시작을 거부합니다.

동적 경계 변경이 차량별 서비스 제한 때문에 특정 층의 마지막 담당 차량을 제거하려 하면 해당 층을 서비스 가능한 차량에 다시 부여합니다. 그래프 연결성을 유지할 수 없는 경계 변경은 직전 유효 구역 배정을 유지합니다.

일반 홀 배차의 `HallCall`에는 출발층·방향·시각·ID만 있습니다. 목적지는 `destination` 알고리즘에만 전달됩니다. 다만 구역/홀짝에서는 **승객이 표지판을 보고 목적지에 맞는 승강기 뱅크를 선택한다**는 가정으로 라우팅 계층이 후보 뱅크를 제한합니다. 이 은행 선택 정보는 임의의 목적지 비공개 공용 홀 호출과 동일한 정보 환경이 아닙니다. 같은 정책 안에서 비교하고 Destination Dispatch는 별도 정보 범주로 해석해야 합니다. 이미 탑승한 승객의 목적지와 차량 내부 예약은 모든 배차에 알려집니다.

## 알고리즘의 실제 구현 범위

14개 알고리즘은 공통 후보/물리 엔진을 사용합니다. FCFS는 예약 순서를, 최근접은 거리, 방향 최근접은 진행 방향 패널티를 사용합니다. Collective/LOOK은 방향별 순회와 마지막 요청 반전, SCAN은 요청이 반대편에 남으면 서비스 범위 끝까지 진행 후 반전합니다. 탑승객이 있는 차량은 목적지 방향의 진행을 보장해 반대 방향 홀 호출 사이에서 무한 왕복하지 않습니다.

ETA는 현재 이동의 잔여 시간, 가감속 이동, 예약 정차 비용의 근사식입니다. 전체 미래 경로를 완전 재시뮬레이션하지 않습니다. Minimum Journey Time은 목적지를 공개받지 않으므로 호출 방향의 평균 남은 이동거리를 대용합니다. 제조사 상용 알고리즘의 정확한 복제가 아닌 문서화된 연구용 구현입니다. 가중 최적화는 대기, 추정 여정, 장기 대기, 부하 균등, 이동거리를 사용합니다.

GA는 8개 이하 호출을 묶어 후보 차량 인덱스 벡터를 탐색합니다. 12개 개체, 8세대, 엘리트 3개, 교차와 65% 확률의 단일 유전자 변이가 있습니다. SA는 64회 이웃 탐색, 초기 온도20, 회당 0.94 냉각, Metropolis 수용 조건을 사용합니다. 둘 다 ETA 기반 가중 비용과 동일 배치의 차량 집중 패널티를 최소화하며 실제 목적함수·탐색·종료가 존재합니다. 전역 최적 보장과 강화학습은 없습니다. `predictive` 유휴 배치는 최근120초의 관측 출발층 최빈값을 이용하는 통계 규칙이며 학습된 AI가 아닙니다.

## 고장

고장은 즉시 신규 승차를 중단하고 홀 예약을 반환합니다. 이미 이동 중이면 예정 정차까지 계속 이동하며, 탑승객을 정규 목적지에 모두 하차한 뒤 퇴역합니다. 이는 갑작스러운 기계 고장을 재현하는 것이 아니라 **안전 퇴역으로 수송 공급이 감소하는 실험**입니다. 운행 중 급정지·구조·비상 탈출은 범위 밖입니다. 특정 뱅크의 마지막 차량이 퇴역하면 해당 승객은 대기·미완료로 남습니다. 수요를 삭제하거나 강제 완료하지 않습니다.

## 지표의 분모와 한계

`generated = waiting + onboard + completed`는 워밍업과 관계없이 전체 도착 승객으로 보존합니다. `unboarded`는 아직 한 번도 탑승하지 못한 승객, `unfinished`는 대기+탑승 중입니다. 기본 wait 통계는 워밍업 이후 등장했고 한 번 이상 승차한 승객의 **현재까지 실제 발생한 승차 대기 누계**입니다. 아직 탑승하지 못한 대기시간은 `currentMeanWait`, `oldestWait`와 대기열에 별도로 표시됩니다. 환승 중 대기하는 승객의 진행 중인 추가 대기는 현재 대기 통계에 포함되며 완료된 것으로 추정하지 않습니다. 여정과 이동시간은 완료 승객만의 통계입니다. 완료 승객만의 지표가 포화 성능을 과대평가할 수 있으므로 미완료·대기열 증가와 함께 해석해야 합니다.

처리량은 워밍업 이후 등장한 완료 승객 / (현재 시각−워밍업), 단위 명/분입니다. Drain에서는 수요 발생을 duration에 중단하고 duration+maxDrain까지 서비스하며 이 기간도 처리량의 시간 분모에 포함됩니다. 워밍업 이전 등장 승객은 계속 서비스하지만 평가 코호트에서 제외합니다. 층별 공정성은 서비스된 출발층 평균 대기시간의 변동계수(낮을수록 균등)입니다. 서비스가 전혀 없는 층은 이 값만으로 드러나지 않으므로 층별 대기열을 같이 확인해야 합니다.

에너지는 완료된 이동 구간에서 `(차체600kg + 75kg×탑승객) × g × 이동거리 × 0.35`를 kWh로 환산하고 정차당 0.0015kWh를 더한 **비보정 대용 모델**입니다. 실제 소비전력, 평형추·회생 제동·효율·대기전력은 반영하지 않습니다. 절대 전력 예측이나 설계 인증에 사용하지 않습니다. 이동 중 구간의 에너지는 도착 때 반영됩니다.

이벤트 로그는 최근100개, 시계열은 시뮬레이션10초 간격이며 snapshot이 통계를 변화시키지 않습니다. 수요300,000명/사건10,000,000회에 명시적 상한을 둡니다. 초기 대기열은 생성 전에 합계를 검사하며 초기·동시·시간별 자동 수요가 공통 상한을 사용합니다. 대규모 전수 실험은 단일 브라우저 메모리와 CPU에 제한됩니다. 완료를 위해 대기 승객을 제거하지 않습니다.
